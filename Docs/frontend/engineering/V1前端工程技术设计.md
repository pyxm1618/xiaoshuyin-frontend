# V1 前端工程技术设计

Engineering Foundation 已冻结，FE-B4 已通过；正式前端开发尚未授权。继承 [总体技术架构 §18](../../总体技术架构.md)、[V1 技术设计 §2、§3、§18.4、§27A、§28A、§30、§37](../../V1技术设计.md) 和 [冻结体验文件索引](../README.md)。

## 工具和运行环境

- 正式客户端采用原生微信小程序、TypeScript、WXML、WXSS。通用交互优先用 TDesign MiniProgram 1.17 stable line。首个适用 Slice 锁定经实测的 exact patch，记录微信基础库和客户端最低版本及覆盖范围。
- 开发和 CI 使用 Node 26.13.0、Bun 1.4.4、TypeScript 5.9.3，与源提交的 CI 和 lockfile 对齐。提交 bun.lock，安装使用 `bun install --frozen-lockfile`。依赖必须有当前用途，直接依赖用 exact version，升级经独立 PR 校验及审计。
- Node 和 Bun 用于工程环节。微信运行时使用平台 API。微信开发者工具负责原生项目编译、预览与上传。首次启用时记录 DevTools 版本及编译和真机矩阵。Bootstrap 验证 TypeScript 合同和治理脚本。
- §27A 绑定 openapi-fetch 与生成类型。其 Request、Response 及 Fetch 行为须对目标基础库实测，普通请求与 §18.4 流式传输分别验证。若适配无法保持合同和流式语义，停止该接入 Slice，记录平台证据并提交上游技术变更请求。

## 目录和依赖方向

`apps/miniprogram/` 是未来小程序根。按真实功能建立 transport、session、页面控制、投影和 presentation，新增目录由 Slice 说明用途。生成合同放在 `packages/generated/`，验证放在 `tests/`，计划和验收放在 `specs/`。

数据接入依赖生成的 paths/components 类型和平台 transport。页面控制调用 HTTP client 和 session，并管理请求生命周期。可独立验证的投影将服务端 DTO 转换为展示数据。页面与组件接收投影、发出意图。公共组件承担跨页面复用的基础交互，避免把业务权限、路由、状态或网络请求封装为组件内部默认行为。

- Session 关联当前 actor、凭证与请求世代，切换主体或登出时取消请求并清除前一受众的内存状态。
- Server State 来源于当前 actor 的服务端响应，保留必要版本和 freshness，按受众及实体隔离，安全和授权相关操作时重新验证。
- Local State 用于明确允许的设备级偏好。Transient Interaction State 用于输入、焦点、提交中、取消、展开和其他界面生命周期。ViewModel 是可重算的展示投影。
- 客户端不得实现 Domain State Machine、Scene Routing、业务资格、Consent、Safety / Compliance 判定或专业判断，不得造状态或维护第二套 API Schema。缺少合同能力时登记 Contract Gap。

## 冻结体验的工程承接

Home / Now、Progress / Journey、Me / Ownership 是冻结的信息架构。Focus Flow 承接交互并交还用户到现实行动，服务端仍拥有业务状态。Journey Chapter、Current Focus 和 Presentation Mode 消费当前授权的业务真相。Family Alliance 与 Phone Use Contract 分开投影，分别保持各自 review 资格和 subject 版本。Child Participation 使用独立的受众和会话范围。

Feedback Event 和 Growth World 从允许展示的事实映射，过程进展与 Outcome 分开。Recovery 遵循 No Punishment、No Debt、No Forced Resume、No Reset。适用的 Safety / Compliance 信号优先呈现；Rights Neutrality 约束反馈和退出。Slice 引用对应冻结章节和验收项。页面布局、视觉、动效、组件样式等待 Step 4 正式冻结及同步。

## 请求、可靠性与隐私

- 使用正式平台认证交换与服务端 session 合同。登录、过期、撤销、退出和 actor 切换显式处理。凭证与内容默认留在最小生命周期内；需要持久化时先验证平台存储能力、过期、清除和威胁模型。禁止凭证、真实家庭正文、儿童标识进入日志、URL、fixture 或公共存储。
- 请求设置可取消、有界超时及上下文标识。晚到响应写入前确认 actor、session 世代、请求或 entity revision；切换页面或 actor 按请求所有权取消。安全读取可对瞬态故障有限重试；写入仅依合同在同一操作范围复用 idempotency key。冲突或 stale 时重读服务端，保留合法草稿并提示用户，等待实际响应才确认业务结果。
- 按 §28.11 分别验证 Loading、Empty、Waiting、Failure、No Permission、Stale Conflict、Retry / Recovery；保留独立的 Blocked 与 Unknown。空态要有服务端证据。可恢复的服务端 HOLD 保持等待和恢复语义；拒绝或硬阻断按真实合同呈现。权限、撤回、Safety、Compliance、重试资格按合同解释。禁止把 unknown、取消、失败、不可用写为完成。
- 缓存最小数据，按取消授权、登出、切换受众、版本或安全状态变化清除；缓存数据不授予业务资格。客户端诊断仅留请求关联 ID、事件类型、脱敏错误码和 timing，避免敏感 payload。
- 按 §18.4 使用 `wx.request` 与 `onChunkReceived` 逐块解码 UTF-8 并逐帧解析。覆盖跨 chunk 字符和 frame、同块多 frame、切后台、网络切换、取消、服务端 INTERRUPTED/STALE。恢复查询持久化 run，按最新授权与版本确认终态。验证真实微信、网关/CDN 缓冲与 chunk 透传。禁止在客户端补造服务器未释放的内容。

## 验证与性能

Unit 覆盖投影、请求生命周期、错误与 parser。Contract 覆盖生成文件、类型检查和对应 HTTP 语义。Integration 连接指定真实测试后端，以合成数据验证授权、版本冲突和恢复。E2E 验收适用旅程。真机验证网络、后台恢复、存储、微信原生交互、流式与平台兼容。Step 4 冻结后按 Slice 检查视觉保真；缺省使用留证对照，达到复用需要时再引入视觉回归自动化。

验收应检查触控、字号、对比、读屏信息、减少动效及替代反馈。使用 DevTools 和真机记录包大小、启动、请求、渲染和资源占用。按测量决定分包与资源策略，检查当前平台限制。性能数字需来自上位要求或可重现测量，经审核后纳入 Slice 阈值。

## 正式应用测试与治理自测

正式应用的投影、transport、请求生命周期及可自动化 Integration 测试采用主仓冻结的 Vitest 基线；适用的 AI / 多轮 / Release / Safety 评测复用主仓 Promptfoo 与经批准的数据及 rubric。Promptfoo 不承担普通 UI 单元测试；前端不得复制后端业务规则或另建模型评测真相。真实微信平台与设备验证继续按适用验收留证。

现有 `node --test tests/**/*.test.mjs` 是工程治理脚本的自测，不是正式应用测试策略的替代，保留其当前实现。首个正式应用测试接入 Slice 在受控工程变更中配置 Vitest，届时更新真实命令、适用的任务验证引用和 CI；本轮不安装运行依赖、不迁移已有治理测试。未来 Integration PR 复用主仓同版本 Vitest / Promptfoo 配置，合并重复入口，保留有独立工程职责的 Node 治理测试，避免同一应用测试由两套框架重复维护。

## 未成年人模式与 Compliance 的前端承接

追溯 `V1产品需求.md` §19A、V1-C39 / V1-C43，以及 `V1技术设计.md` §7.7A、§27B.3、§32.5A。年龄段、minor mode、当前 guardian 和同意的 purpose / scope / version / validity 以及 feature applicability 由服务端拥有。客户端只呈现当前合法 viewer 可读的事实和服务端限制，不以本地偏好、页面生命周期、自报年龄或 family membership 推导资格，不复制 Compliance Policy。

- UNDER_14 必须先经严格最小化的监护人告知及有效同意流程，之后才可建立正式 child profile；现有最小同意文案不自动授权后续 Assessment / Case / AI 数据处理。UNKNOWN、缺失 provenance、scope 不足或撤回不得当成成人或已同意。identity-binding confirmation 与 guardian consent 分开。
- 从 `GET /api/v1/compliance/profile`、`GET /api/v1/me` 和当前受限操作响应承接适用状态；guardian consent / notice 合同仅代表当前公开能力，不能推导尚未公开的任意 purpose 或子女全部资料权限。
- 连续使用提醒只在服务端判定功能适用时执行；依当前服务端累计事实与应提醒信号呈现每超过 2 小时等适用提示。刷新、切后台、换设备或重新登录不能简单清零；本地 timer 只能服务展示，不成为计量或适用性真相。
- 当前生成合同未公开完整 feature applicability、跨设备 interaction usage / reminder 的客户端接入能力。对应 Slice 在获得正式合同及测试环境前 BLOCKED，不设计替代 API，不自行用客户端规则补齐。不得把缺失响应当成 NOT_APPLICABLE 或“未到提醒时间”。

适用验收须覆盖同意拒绝/撤回、过期或变版、年龄/guardian UNKNOWN、受众切换、A4003 对 minor 阻断，以及服务端适用/不适用/未知、跨设备与刷新计时连续、到期提示、网络失败恢复。记录实际服务端响应、policy / consent version、环境和结果；Legal / Compliance 批准与真实设备证据未具备时保持 BLOCKED / NOT VERIFIED。

## V1 最小运营端工程归属

`V1产品需求.md` §22.2 与 `V1技术设计.md` §2、§28A、§38 Phase 5 是 Operations 的上位依据。前端工程交付责任包含未来 `apps/operations/` 的 React + Vite + Refine 实现、测试及验收证据；产品、Staff capability、scope / assignment、专业与法律批准、领域及 API 合同继续归主仓对应 Authority / 后端 owner。Owner 在批准的 Slice 指定实际交付人和验收责任，未指定或依赖未具备不得宣称运营已就绪。

Phase 5 承接专业包版本、Safety / exception、Data Rights、质量抽查、开放范围及必要运行观察；依赖 Phase 1 身份/Staff/授权与后端相应专业、Safety、权利、运营合同，Phase 6 真实家庭开放前须完成适用验收。仅有 `/api/v1/staff/me` 与 capability grant/revoke 定义不足以覆盖运营业务。本轮登记其责任，不创建应用、页面、包或独立后台规划；家庭微信小程序的 Journey 与 Step 4 设计不承担运营后台。正式上线前，前端交付实际操作及权限/失败证据，后端验证 capability / scope / assignment / audit，独立 Audit 2 检查当前候选，Owner 对真实运营承接与上线准入负责。

## Owner 确认的实施决策与外部 Authority 依赖

本节承接 Product Owner 已确认的决策，不新增产品需求、页面、数据、状态或 API；上位 Authority 继续优先。

- **微信小程序**：Owner 确认的正式名称为“小树荫助手”。沿用现有微信小程序主体及 AppID，不另建家庭用户端产品。必要申请材料已齐全，但这不代表生产审核、平台能力或合规验收已经通过，这些仍由适用 Slice 取得真实证据。`apps/miniprogram/` 按全新开发处理，不要求继承或复用历史代码。历史用户、历史数据及迁移需求保持 UNKNOWN，不得自行假设，也不预建迁移能力。
- **业务边界**：依 `V1产品需求.md` §1.3、§1.4，V1 正式业务为当前 Digital Use 问题。最小分诊只呈现服务端对服务范围的判断、合法分流、退出与现实支持，不开放其他儿童问题的完整干预流程。共同确认或共同可见的内容限于当前 Case 内服务端授权的可见范围，不建立独立的家庭共享空间或多人私人空间，客户端不自行推导可见性。
- **体验质量**：完整保留[开发与验收规范](V1前端开发与验收规范.md)中的 Experience Quality Gate 及独立否决权、五个质量维度、七个 Core Moment、Signature Experience、游戏化体验、正反馈与情绪回应、Reality First、非惩罚性与长期连续性，以及 Motion / Sound / Haptics 设计空间。Growth World 保持 “not everywhere, but not nowhere meaningful”，在适用核心体验中必须有实际贡献，不降级为可选装饰；它只消费合法、真实、viewer-scoped 的服务端事实，不新增独立持久化的成长数据、状态、事件、等级、积分、养成或排行榜，不承担授权、业务状态、Outcome 或导航职责。具体表现形式由 Step 4 决定。
- **内容表现形式**：三格漫画、教学动画、教学音频等不纳入当前 V1 必做开发任务，不建设漫画、教学媒体或媒体管理模块及相关基础设施。轻量化、情境化、多样化表达的体验原则保留，具体形式不提前冻结。该决定与前端体验层的 Motion / Sound / Haptics 无关，后者仍属已确认的体验设计范围。
