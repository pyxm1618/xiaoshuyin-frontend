# V1 前端开发与验收规范

FE-B1 候选，待 FE-B4 独立审计。适用于工程、合同接入和业务实现 Slice。

## 编号与交付

业务标识用 `FE-001`、`FE-002`，目录依官方 Spec Kit sequential 规则使用 `specs/001-fe-<slug>/`。使用 `--short-name fe-<slug>`，冲突时以脚本实际输出的编号为准；只在当前受控 checkout 创建。未来按现有目录名迁入主仓库前端命名空间或经 Integration PR 映射，保持 FE 标识并验证工具路径。Bootstrap 使用 FE-B0–B3 并在 FE-B4 前停下。

| 阶段 | 人员与产物 |
| --- | --- |
| Specify → Clarify → Frozen Spec | Plan AI 1 读取 Authority 并冻结 Spec。正式实现由 Developer AI 执行。 |
| Plan → Checklist → Tasks → Analyze | Plan AI 2 依据冻结 Spec 制定实现合同，列明验证证据与本轮适用验收。 |
| Audit 1 | Plan AI 2 做 pre-implementation 审计，检查 exact spec / plan / checklist / tasks、依赖、路径和风险，解决 finding 后准入开发。 |
| Implement → Test → Converge | Developer AI 按已准入任务实现和验证，对照上游与真实合同收敛，在 PR 上公开当前候选证据。 |
| Audit 2 | 独立 AI 对准确 PR head 只读、对抗性地读取完整 diff、相邻实现、真实测试和适用证据，记录 PASS 或阻断及 SHA；随着 head 变化失效。 |
| Merge main | Owner 在 CI、独立 Audit 2、讨论解决和其他适用批准证据齐全后执行。 |

审核从具体 finding 出发并限于当前 Scope。未读完整 Exact Head、上游冲突、真实能力不足、测试无法执行或独立角色缺失时 STOP 并记录。修复后复查受影响范围和当前 head。Developer AI 不得完成自己的审计二，CI 通过也不代替审计。禁止缩减标准、伪造证据、借机扩大 Slice 或无止境重复审核。

## Slice 合同

Spec 列 Scope、Non-goals、上游文件及段落/ID、依赖和真实能力、可观察的 acceptance。Plan 限定 Allowed Paths、Forbidden Paths、Verification Commands、STOP Conditions、环境和测试数据，标明视觉及真机适用性。任务用稳定 ID 标注 `[REQ:...]` 和 `[VERIFY:tests/...test.mjs]`，完成项带当前变更绑定、任务摘要、测试文件和实测证据。详见 [规格入口](../../../specs/README.md)。

实现前在单独受审的治理变更登记有限实现路径的 Ownership。共享路径记录联合所有者或使用显式依赖顺序。并行 Slice 独立 checkout、基线和 PR，触碰共享路径前协调，基线变化后重跑受影响检查。实现 PR 改动必须收敛在已登记且 Plan 允许的路径，禁止修改上游 Authority、治理或其他 Slice 来授权自身。

## 适用验收

1. Engineering Correctness 覆盖静态检查、可复现依赖、工程边界、故障处理、治理和必要测试。
2. Business / Contract Correctness 覆盖实际 API、类型、错误、受众、状态真相、版本、并行主线和失败路径。
3. Experience Correctness 对照冻结设计的正确性与体验门禁，覆盖关键状态、真实中断与恢复。
4. Visual Fidelity 在 Step 4 冻结后，核对指定设计版本、关键状态与尺寸并留对照证据。
5. Real-device Acceptance 记录设备/系统/微信/基础库/DevTools、构建、后端环境、操作、实际结果以及相关缺陷。

仅执行 Scope 适用的条目，未启用的能力显式标记。PR 记录 Exact Head、CI run、独立审计条目、依赖变更和未验证项。对真实条件未具备的条目保持 BLOCKED 或 DEFERRED。

## 准入工件与工程路径

实现前在规划 PR 合入冻结的 Spec、Plan、Checklist、Tasks、Analyze 及由 Plan AI 2 形成的 Audit 1 证据。证据绑定五份工件摘要。开发提交重用已合入基线的证据，只能在保持任务定义字节一致时更新完成标记。共享工程配置可在正常规划 PR 登记需要的路径，由同一实现 PR 交付，治理规则和 CI 的变更走治理 PR。详细格式和路径入口见 [规格入口](../../../specs/README.md)。
